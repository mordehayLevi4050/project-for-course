# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GrouPay v1: a Hebrew-first (RTL), offline, single-phone Android app (Flutter) for splitting group-trip expenses and producing the minimal list of transfers that settles the group. The user (Motty) communicates in Hebrew; planning documents are written in English.

**Current state:** `lib/main.dart` and `test/widget_test.dart` are still the throwaway scaffold (a Hebrew literal, `com.example.groupay`, debug-key release signing). The first story replaces them. Everything below describes the *target* architecture. New code must follow it even though the scaffold does not.

## Architecture (from the spine)

Layered ports-and-adapters, feature-first, with one composition root.

```
lib/shell/      main(), go_router, ProviderScope overrides (the only place that knows concrete impls)
lib/core/       db/ (all drift tables), ports/, policy/, result/, money/, text/, i18n/, ui/{theme,widgets}
lib/features/   groups/ and expenses/ {ui,app,domain,data}; settle_up/ {ui,app,domain} (no data/, it owns no table)
assets/fonts/   Heebo (bundled, no runtime font fetching)
test/           mirrors lib/
```

| Layer | May import |
| --- | --- |
| `shell/` | everything |
| feature `ui/`, `app/` | own `app/` and `domain/`, `core/` (non-db), lower features' `domain/` and `app/` |
| feature `domain/` | `core/` (non-db, non-ui), lower features' `domain/` |
| feature `data/` | own `domain/`, `core/` (including db), lower features' `domain/` interfaces |
| `core/` | no feature, no `shell/` |

Rules that need reading several files to see:

- **Dependency direction:** `settle_up → expenses → groups` (imports go downward only). When `groups` needs a fact owned by `expenses`, it goes through a port in `core/ports/` (`PayerUsagePort`, `GroupTotalsPort`), implemented in `expenses/data`. Features navigate by route path, never by importing each other.
- **`domain/` is pure Dart:** no Flutter, drift or Riverpod imports. Only `data/` and `core/db/` import drift. All tables are declared in `core/db/tables/`. Generated `*Row` classes stay in `data/` and are mapped to domain entities.
- **Table ownership = write rights:** `groups` writes `groups`, `members`, `app_settings`. `expenses` writes `expenses`. `settle_up` only reads.
- **Riverpod only** (`@riverpod` generator). Reads wrap repository `.watch()` streams; no manual caching or refreshing. Writes are notifier methods. Repository providers are declared in the feature's `app/` and throw until `shell/` overrides them. The database, repository and port providers are `keepAlive: true`. Port implementations depend only on `AppDatabase`, which keeps the provider graph acyclic. `setState` is only for ephemeral widget-local input.
- **Writes:** one `db.transaction` per user action, on the single `AppDatabase` instance. Inside it, gather facts, call the pure `core/policy` function (`Verdict`), then write. Return `Result<T>` / `Failure(MessageKey)`. Exceptions are only for bugs or I/O faults. Guards never live only in the UI. The policy set is closed: a new guarded rule goes into `core/policy`, never into a feature.
- **Save once (AD-23):** the entity id (UUID v7) is generated when the form opens. The insert does nothing if the id already exists. Notifiers ignore calls while a save is in flight.
- **Money:** `Tenths` (an extension type over `int`, ₪0.10 units). `double` never holds money. Display only via `formatShekel()`.
- **Order:** `saveSeq` / `memberSeq` (MAX+1 per group, set once), never timestamps or row ids. Times are UTC epoch millis set by repositories.
- **Split is never stored:** the Transfer list is one pure function in `settle_up/domain`. It does an exact search over zero-sum partitions, never greedy matching (see `transfer-calculation.md`).
- **Names:** normalization, `nameKey` uniqueness, grapheme length and Hebrew-first collation live only in `core/text`. Never use SQL `lower()`/`NOCASE` on names.
- **Strings:** no Hebrew literals in widgets. All text comes from the `MessageKey` table in `core/i18n`. User names enter sentences only via `isolateName()`. Fixed messages must match the spec exactly.
- **UI:** no color, font-size or radius literals in feature `ui/`. Use `core/ui/theme` tokens (light-only theme) and the shared widgets (`AppScaffold`, `showAppSheet<T>()` where `null` means dismissed, exit sheet, `memberColorIndex()`/`avatarLabel()`, snackbar helper). Only the two animations allowed by EXPERIENCE.md exist, through one helper that respects `disableAnimations`. Text scale is clamped to 1.5 in `shell/`.
- **Navigation:** only `go_router` in `shell/` navigates. Route tree: `/` → `create`, `group/:id` (`add`, `edit/:eid`, `settings`, `summary`), `archive` (`group/:id` and its `summary`). `shell/` reads `activeGroupId` before `runApp` and passes it as `initialLocation`. After a Group is created or restored, call `go('/group/:id')`. A redirect blocks `add`/`edit`/`settings` for an Archived group. Read-only mode comes from `isGroupMutable`, never from the route. Unsaved input is guarded by `PopScope` and the exit sheet. Every route uses `NoTransitionPage`.
- **Active group** is `app_settings.activeGroupId` (single-row table owned by `groups`; no shared_preferences). Archiving a Group clears it in the same transaction.
- **Hard delete** for Members and Expenses (no `deletedAt`). Groups are only archived, never deleted.
- **Schema:** `beforeOpen` sets `PRAGMA foreign_keys = ON` and `synchronous = FULL`. `expenses(groupId, payerId)` references `members(groupId, id)` with `ON DELETE RESTRICT`. Category is a Dart enum stored as a stable string key that is never renamed. On every schema change: bump `schemaVersion`, run `make-migrations`, and commit the snapshot and the generated migration test.
- **Android:** `applicationId` `com.mordehay.groupay` never changes (debug adds the `.dev` suffix). minSdk 35. Backup is disabled (`allowBackup="false"`, `dataExtractionRules` exclude every domain). Builds installed as `com.mordehay.groupay` are signed with the release keystore, which is kept outside git. Android-only plugins must sit behind an interface in `core/`.

## Testing expectations

- Unit-test every `core/policy`, `core/text` and `core/money` function, plus the transfer calculation for every NFR-16 case (10 Members in ≤1s).
- Test repositories against `NativeDatabase.memory()`.
- Summary golden tests use bundled Heebo, run at text scale 1.0 and 1.5, and include Hebrew, Latin and mixed names.
